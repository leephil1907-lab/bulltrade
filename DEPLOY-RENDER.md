# Deploying Blockchain Bullhorn to Render

Live service: **https://blockchainbullhorn.onrender.com**
Blueprint: `render.yaml` (already committed — no hand-setup needed)

---

## 1. Push the branch to GitHub

The work sits on `polish/responsive-admin-and-visual-refresh`. Nothing is pushed yet.

```bash
cd bulltrade
git remote add origin https://github.com/leephil1907-lab/bulltrade.git   # if not set
git push -u origin polish/responsive-admin-and-visual-refresh
```

To land it on the deployed branch instead (`main`):

```bash
git checkout main
git merge --no-ff polish/responsive-admin-and-visual-refresh
git push origin main
```

> Render's `autoDeploy: true` means a push to the connected branch deploys
> automatically. A push to any other branch does not — either merge to the
> connected branch or point the Render service at this branch in
> **Settings → Build & Deploy → Branch**.

## 2. What the blueprint creates

| Setting | Value |
| --- | --- |
| Service | `blockchain-bullhorn` (Node, `plan: starter` — always on) |
| Build | `npm ci --omit=dev` |
| Start | `node server.js` (direct, so SIGTERM flushes `db.json`) |
| Health check | `/healthz` |
| Disk | `bb-data` → `/var/data` (1 GB, persistent) |
| Data dir | `DATA_DIR=/var/data` |
| Canonical URL | `SITE_URL=https://blockchainbullhorn.onrender.com` |

`SITE_URL` drives canonical/OG tags, `robots.txt`, `sitemap.xml` and every
link in outgoing email. If you attach a custom domain later, change it in the
dashboard and everything follows.

## 3. Secrets to set on first sync

Render prompts for any key marked `sync: false`:

| Key | Notes |
| --- | --- |
| `ADMIN_EMAIL` | login for `/admin` |
| `ADMIN_PASSWORD` | **strong** — the admin console can move money |
| `SMTP_*` (or `EMAIL_TRANSPORT=sendgrid` + `SENDGRID_API_KEY`) | verification and review emails |
| `DEPOSIT_ADDRESSES`, `PRODUCT_PAYMENT_ADDRESSES` | optional; can also be set in Admin → Settings |
| `BACKUP_REPO` + `BACKUP_TOKEN` | optional off-site mirror of the disk |

`JWT_SECRET` is generated by Render (`generateValue: true`). Do not paste one in.

## 4. Verify after deploy

```bash
curl -s https://blockchainbullhorn.onrender.com/healthz
curl -sI https://blockchainbullhorn.onrender.com/ | head -5
curl -s https://blockchainbullhorn.onrender.com/sitemap.xml | head -5
```

Then in the browser:

1. `/admin` → log in → **KYC Review** shows the country queue.
2. `/markets` → the session bar clock ticks and the breadth bar fills.
3. `/` → footer shows the Facebook page card and the six-column sitemap.
4. `/kyc` (signed in) → the three-step verification wizard.

## 5. Notes specific to this project

- **One instance only.** A Render disk cannot be shared, so `numInstances: 1`.
  Deploys therefore have a few seconds of downtime; `server.js` flushes
  `db.json` on SIGTERM so nothing is lost.
- **Free plan is not viable here.** It has an ephemeral filesystem — the JSON
  database and every KYC upload were wiped on each deploy. `plan: starter`
  (~$7/mo) + a 1 GB disk (~$0.25/mo) is the minimum that actually persists data.
- **Region matters for latency from Nigeria.** Choose `frankfurt` at creation
  time (Render cannot change region afterwards): ~120–150 ms from Lagos versus
  ~190 ms for Virginia.
- **KYC uploads** land in `DATA_DIR/uploads/<userId>/`, served to admins only
  through `/api/admin/kyc-file`.
- The blueprint sets `RATE_LIMIT=on`; leave it on in production.
